## 裁示 60–61（T3，通則，雙方拿到完全相同的內容）

該問於 T3 重提,現予補答。漏答是裁判的疏失,不是提問方的問題。

### 裁示 60：「干擾」凍結的是**編隊**，但同格全體都會被凍住

引擎的實作（`arbiter.bombard`）:

```
if freeze:                          # 只有「干擾」的 freeze 為 True
    tgt["flags"]["hit"] = True
    tgt["flags"]["interdicted"] = True
```

`tgt` 是**單一目標編隊**,所以就引擎本身而言,凍結是**編隊層級**,不是格層級。

`interdicted` 旗標的作用（`arbiter.dig`）:

```
if u["flags"].get("interdicted"):
    return None                     # 該小時不得構築工事
```

——**只封鎖構築工事**。而不能休整是另一件事,由 `hit` 旗標造成（裁示 58）,
三種火力任務都會設 `hit`。所以:

| | 凍結構工 | 凍結疲勞消退 |
|---|:---:|:---:|
| 急襲 | 否 | **是** |
| 壓制 | 否 | **是** |
| **干擾** | **是** | **是** |

#### 但同格全體仍會一起被凍住 —— 因為裁示 48

裁示 48 已定:對某格射擊時,**該格所有敵方編隊都在彈著區內,一律承受**,
總發數按人數比例分攤。既然每個佔用編隊都實際承受了該次射擊,
**每一個都會被設上 `hit`,若任務為干擾則每一個也都被設上 `interdicted`。**

所以答案是:**引擎的凍結是編隊層級,但經由裁示 48,一次干擾射擊會凍住該格的全部編隊。**
兩個師疊一格,一次干擾同時凍住兩個。

**這對雙方同樣成立**,而且與裁示 48 已揭露的另一件事互為代價:
疊放讓對方一次射擊就凍住你兩個師,同時本局不實施密度懲罰、疊放比現實安全。
**疊放的利與弊都在這裡,雙方自行權衡。**

### 裁示 61：抽離砲兵營的發數按門數等比縮放，且照樣設 `hit`

**兩問皆為是。**

#### 發數按實際門數縮放

`arbiter.bombard` 的算式:

```
mix   = 該編隊的火砲編成
scale = 該編隊現有火砲門數 ÷ 編成標稱門數      ← 戰損後亦按比例遞減
guns  = 各砲種標稱門數 × scale
發數  = guns × 射速 × 佔用分鐘 × 彈量倍率
```

所以一個 12 門砲的營,其標準任務發數就是 48 門砲師級任務的四分之一。
**沒有規模門檻,沒有最低發數。** 而且 `scale` 用的是**現有**門數——
被反砲兵打掉的火砲會等比降低此後每次射擊的發數。

#### 旗標照樣設，且沒有程度之分

`tgt["flags"]["hit"] = True` 與 `interdicted` 的設定**不看開火方的規模**。
一個 12 門砲的營實施干擾,與一個 210 門砲的軍集中干擾,對
「目標該小時不得構築工事、不得休整」的效果**完全相同**。

#### 裁判必須主動指出這條規則的後果

由裁示 58、60、61 合起來,可以得到一個**規則允許、成本極低、效果極強**的做法:

> 把砲兵抽離成多個獨立的營,各自對**不同的**敵編隊實施干擾。
> 每個營只花標準任務 0.4 倍彈量的其中一小部分（因為門數也只有幾分之一）,
> 就能讓那個敵編隊該小時**既挖不了工事、也回不了疲勞**。
> N 個砲兵營可以同時凍住 N 個敵編隊。

**裁判在此明白揭露這件事,並說明為什麼不在本局修改它:**

1. 規則已於 T0 凍結（`law_of_war.md` §0.1）。要修正需改 `flags["hit"]` 為程度量,
   那會連動傷亡、休整、工事、能見四個系統的校準。
2. 它並非完全不合史實。**這正是「擾亂射擊」（harassing fire）的定義**——
   1944 年的砲兵確實以低速率、長時間、鋪開的落彈剝奪對方的睡眠與作業能力,
   而那不需要多少砲。
3. 但**「一發砲彈與一次師級集中射擊效果完全相同」確實是模型的失真**。
   真實的擾亂射擊會降低作業效率,不會歸零。

**已記入判例集,兩局之間修正。本局雙方皆得使用此做法,且已同時知道它存在。**

裁判寧可讓雙方都看見一個失真的規則,也不願讓它只被先想到的一方使用。
