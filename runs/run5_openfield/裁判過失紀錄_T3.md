# 裁判過失紀錄 — Tick 3（雙方收到字面完全相同的一份）

## 過失 1：裁判在私訊中給了**一方**錯誤的時間資訊

我在通知**藍軍**「Tick 3 已可下令」時，附了一句「天亮了（06:00 起白天）」。

**那句是錯的。** Tick 3 是 `1944-08-26 00:00–05:00`，**全程夜間**（gh23 為黎明），
天亮要到 Tick 4（gh24 = 06:00）。我把 tick 編號與時刻算錯了。

**不對稱性**：這句錯話只有藍軍收到，紅軍沒有。紅軍自行算對了時間。
若藍軍據此把夜間排成白天作息，其夜行軍疲勞（+8/hr）與移動減半（×0.5）
都會與它的計畫不符。

**補救**：已立即通知藍軍該句作廢，並告知它可以無限制重寫 `命令_T3.md`。
本則紀錄同時送達雙方並寫入戰史。

**制度性教訓（記入 `precedents.md`）**：
戰報是唯一權威來源，裁判的訊息不是。`戰報_T3.md` 的標頭本來就正確寫著
`1944-08-26 00:00 夜間` —— 錯的是我額外加的那句話。
**這正是「單方內容一律由程式產生」那條規則要防的東西**：
我手寫的每一句單方訊息都是一個可能出錯、且無法被對稱驗證的通道。
先前我把這條規則只套用在「事實性資訊」上，但時間、天候這類**共同事實**
同樣不該由我口述——它們本來就在戰報裡。

**今後的做法**：裁判給任一方的通知，只寫「新檔案已放好、去讀它」，
不重述任何戰報裡已有的內容。
