# 判例表 Precedents — 純戰場 The Open Field

> **這份檔案跨對局累積。** 裁判每次替一個新姿態／新編成／新戰術裁定係數，就寫一筆進來。
> 之後**任何一方**出現類似情境，必須沿用同一筆；要改判必須寫明「為什麼這次不同」。
>
> 判例不是把可能性列舉完，是把**判斷過程留下痕跡**。指揮官下了裁判沒想過的陣型時，
> 裁判當場判它自己的值——可以落在所有現有判例之外——但判完就 binding。

## 〇、不可變動的部分

### 尺度的意義（這把尺不能動，動了就沒有東西可以比較）

**砲擊暴露係數**：`1.0` ＝開闊地行軍縱隊、完全暴露　↔　`0.03` ＝地堡
**兵力比 → 損失**：`combat_v1.md` §III 對照表，一行不改
**戰鬥力 CP 的九個因子**：`combat_v1.md` §II，因子清單不變（各因子的**值**才是判例的範圍）

### 裁定時點（最重要的一條）

```
指揮官在命令裡描述姿態
   ↓
裁判當場裁定係數 ＋ 寫下依據 → 同時公告雙方 → 寫進本表
   ↓  ← 此時裁判還不知道誰會被打、打多重
進入解算（引擎照該係數執行，不再重判）
```

**在這個順序下，裁判不可能挑一個對誰有利的數字，因為判的時候還不知道誰會受益。**

若情況是解算中途才浮現（沒人宣告但事實發生），裁判當場判、立即公告，並**必須同時寫明此判決對哪一方有利**。

### 指揮官的主張權

指揮官可以在命令裡主張：「我這個部署應該算 X，理由是 Y」。裁判裁定後公告雙方，成為新判例。
（Run 4 藍軍全局提出 30 餘個規則問題、產生 45 條裁示，是本制度的雛形。）

## 二、彈著覆蓋與密度判例

**Run 4 的做法有結構性錯誤，已廢止**：當時用單一「密度係數」同時代表「目標本身多疏」與
「目標有多少落在彈著區內」，並依**兵力**分級（師 0.20／旅 0.15／營 0.30／小單位 0.12）。

**改正後的形式**：
```
傷亡 = 發數 × 每發殺傷力
       × 彈著區對目標的覆蓋率   ← 判例（看指揮官描述的疏開程度與彈著散布）
       × 該處防護（暴露係數）
```
一個 hex ＝ 2km × 2km ＝ **4 km²**；一次集中射擊的彈著散布約 200×200m ~ 500×500m
＝ **0.04–0.25 km²，佔格子面積的 1–6%**。覆蓋率必須反映這個量級。

## 三、砲擊殺戰車判例 ★Run 4 最大的錯誤

`determinism_v1` §III 原文：「100 發 105mm vs **100m 內**開闊戰車 = 0.5 輛/百發」→ 0.005/發。
**限定詞是「彈著點 100m 內」。** Run 4 把它套在整個 2km 格子的編隊上、每一發都算，
等於假設每發砲彈都落在戰車旁邊。

後果：全場 128 輛戰車損失中 **83 輛（65%）死於砲擊**；藍軍 8,813 分中 **2,280 分（26%）來自戰車**。
歷史上（諾曼第 ORS 調查）砲兵**直接擊毀**戰車的比例極低，主要價值是壓制與癱瘓機動。

**連鎖後果（比數字本身更嚴重）**：
> 砲兵隔 4 格穩定殺戰車、零風險；戰車要互射得進到 1 格、還吃攻擊 ×0.7。
> → 理性的裝甲師永遠不該前進 → **Run 4 全局戰車對戰車直射交戰 0 次**
> → `determinism_v1` §I 命中係數表、`combat_v1` §IV 穿甲表——規則書最精細的兩個系統——**一次都沒用到**。

| # | 情境 | 判法 | 依據 |
|---|---|---|---|
| T1 | 戰車在彈著點 100m 內、開闊 | 0.005/發（105）、0.02/發（155） | `determinism_v1` §III 原文 |
| T2 | 戰車散佈於 2km 格內、砲擊該格 | **待判**：須先乘「彈著區覆蓋率」（見二） | Run 4 錯在跳過這一步 |

## 八、經驗與命中 ★結構性修正（Run 4 之後定案）

### 問題

Run 4（與規則書原狀）的結構缺陷：**只有戰車有「命中」這個環節。**

```
戰車（determinism_v1 §I）：命中數 = 發數 × 命中係數 × 修正（距離/天氣/**經驗**/疲勞）→ 穿甲表
砲兵（determinism_v1 §III）：傷亡 = 發數 × 每發殺傷力 × 暴露 × 密度     ← 無命中環節
步兵（combat_v1 §II）：      CP 九因子相乘                              ← 經驗壓成籠統乘數
```

「每發殺傷力 0.30 人/發」是**命中率與單發威力被揉在一起**的數字，揉在一起經驗就無處可進。
後果：Run 4 中特戰旅的 ⭐⭐⭐⭐⭐ 只在唯一一場地面戰生效過一次，其餘 7 個 tick 完全沒作用。

### 定案的形狀（把戰車的形狀推廣到所有兵種）

```
效果 = 發數 × 命中／有效彈率 × 單發效果 × 目標防護
                  ↑ 經驗在這裡，而且只在這裡
```

| 兵種 | 「命中」的實際內容 |
|---|---|
| 步兵 | 有效射擊比例、火力紀律（新兵打高、老兵等目標進有效距離） |
| 砲兵（間瞄） | **觀測員修正射效率 ＋ 砲班散布圈**（老 FO 兩次修正跨叉，新 FO 六次還在浪費彈） |
| 戰車（直瞄） | 規則書已有：⭐ 0.70 / ⭐⭐ 0.85 / ⭐⭐⭐ 1.00 / ⭐⭐⭐⭐ 1.05 / ⭐⭐⭐⭐⭐ 1.10 |
| 偵察 | 回報正確率（番號、數量、座標精度） |

### 不可重複計算：經驗有兩個入口，互不重疊

| 入口 | 代表什麼 | 用在哪 |
|---|---|---|
| **CP 乘數 0.75–1.30**（`combat_v1` §II，規則書既有） | 戰術素養與凝聚力 | 地面戰（近接/突擊/守備）——此處不計發數 |
| **命中率**（本次新增） | 射擊技術與觀測品質 | 所有**計算發數**的射擊：步兵火力、砲兵、戰車、迫砲 |

兩者不重疊，因為地面戰 CP 公式裡沒有「發數」這個量。

### 待裁定（首次遇到相關情境時當場判、公告雙方、回填本表）

| # | 待判項目 | 已知參考 |
|---|---|---|
| X1 | **間瞄砲兵的經驗帶寬** | 規則書給直瞄戰車 ±10%；但歷史上間瞄的 FO/FDC 訓練差距遠大於此（老 FO 與新 FO 的耗彈量可差 2-3 倍）。帶寬應寬於 ±10%，具體值待判 |
| X2 | 步兵火力的有效射擊比例隨經驗如何變 | |
| X3 | 觀測品質對砲擊的影響（FO 修正射 vs 地圖射擊 vs 無觀測） | `combat_v1` §VI 有時序（呼叫後 3-7 分開火、精度誤差 50-75m），無係數 |

### 部隊素質退化（引擎該記帳的部分）★裁判曾判錯，此為更正版

**錯誤版本（已廢止）**：「老兵先死，傷亡按老兵優先扣減」。

**文獻方向相反：新兵/補充兵的傷亡率明顯高於老兵。** 二戰歐陸的個別補充兵制度出名的問題就是——
補充兵被單獨塞進正在接觸的部隊，班長還沒記住他的名字，他就：散兵坑挖太淺、聽不出彈道該趴時在跑、
遭火力時擠成一團、不知道自己班的火力配置與撤退路線。他在加入後**頭幾天**的傷亡率遠高於老兵；
老兵活下來正是因為已經學會這些。

**唯一「先死」的是幹部**：班長、排長、連長因為要指揮、要暴露、要帶頭，傷亡確實不成比例集中。
但其意義不是「老兵被消耗掉」，而是**部隊失去了傳遞經驗的管道**。

**正確的退化機制（三個來源）**
1. 補充兵大量湧入 → 稀釋 `veteran_fraction`
2. 幹部傷亡 → 經驗傳遞中斷，剩餘老兵的經驗無法擴散到新兵
3. 建制凝聚力被打散 → 班排的默契重建需要時間

**關鍵推論**：一個被打殘的師**補滿員之後不是復原，是變成一個更容易崩的師**——
因為新補進來的那批接下來會死得更快，形成複利式衰退。

Run 4 實例：RED-1 損失 3,024 人（22%），XP 從頭到尾維持 3。
若有此機制，它補充後的下一個 tick 會**比補充前更糟**：命中率下降 → 砲兵輸出下降 → 傷亡再上升。

**引擎該記的帳**：`veteran_fraction`（老兵佔比）、`cadre_fraction`（幹部佔比）、補充兵到位時間與數量；
傷亡分配時**新兵承受的比例高於其人數佔比**（具體倍率待裁定）。48 小時內經驗不會上升，但稀釋是立即的。

## 9.1 ★ W1 的要件 C 有兩個獨立的缺陷（本局最重要的產出）

W1「攻擊已喪失戰鬥力之編隊」要求三要件同時成立，其中
**要件 C：無脫離能力＝補給走廊切斷**。

### 缺陷一（裁判自己的認定）：C 把兩件不等價的事綁在一起

測試案例：藍軍 BLU-3-rcn 終局 **兵力 124/300（傷亡 58.7%）、組織度 2.0、
火砲 0、戰車 0、全局五十四小時從未開火**，承受十二小時集中砲擊。

- 要件 A 成立（傷亡 ≥50% 且 org ≤25）
- 要件 B 成立（未攻擊、火砲存量 0）
- **要件 C 不成立**（補給走廊全程 intact）

→ W1 不成立。**在任何常識判斷下該編隊早已喪失戰鬥力，但規則說沒有。**
「無法脫離」與「無法作戰」是兩件事，C 把後者的判定綁在前者上。

### 缺陷二（敗方在覆盤中提出，比缺陷一更嚴重）

裁示 43 自行公開過：`compute_supply` **不為抽離的營級單位計算走廊**
（`if u.get("is_detachment"): continue`），故抽離單位的補給狀態多數情況沿用「完整」。

與要件 C 相乘的結果是：

> **任何營級單位都不可能滿足 W1，無論它被摧毀得多徹底。**

「禁止在屍體上收割殺傷分數」這條禁令，恰好對**最容易變成屍體的那一類單位**失效。

（敗方同時誠實註記：本案即使逐格計算，C 也會因事實而不成立
——紅軍從未進入 row 11 的 x ≤ 13。所以這是制度缺口，不是該方在本案的冤屈。）

### 待決修法（Run 6 前擇一或並行）

1. 為抽離的營級單位計算補給走廊（修 `compute_supply`）。
2. 要件 C 改為「無法脫離**或**無法作戰」（把 and 改成 or）。
3. 對某一規模以下的單位，C 改為可操作的判準：
   殘餘移動率低於攻擊方，或處於攻擊方火力範圍內且無脫離路徑。
4. 另立一條獨立禁令：對已無任何武器、且持續不還擊之編隊的持續砲擊。

**注意時序紀律**：本局已於 T0 凍結規則，故不得依此改判 Run 5。
修法自 Run 6 的 T0 前公佈後生效。

## 9.2 前進指揮所缺少「必須在前」的檢查

`command.delay_tier_adjust` 只檢查「軍長是否駐前進指揮所」與「距離是否 ≤ FWD_RANGE」，
**沒有任何「必須比本方主力更前」或「必須接近敵方」的條件**。

Run 5 藍軍因此把前進指揮所設在自己**後方縱深的森林格**（與主指揮所同格、三個營守備），
零斬首風險取得 0 級命令延遲。這使設計上原本要互相交換的「節奏優勢 ↔ 斬首風險」完全脫鉤。

本局已公開揭露、雙方皆可使用（紅軍隨後也設了一個，位置較誠實地在主力之前一格），本局不修。

待決修法：前進指揮所須位於本方主力重心之前，或距最近的已偵獲敵編隊若干格內。

## 9.3 觀測即開火權（裁示 56＋58）是一組極強的機制

- 裁示 56：砲兵不需自身視距內偵獲，該方**任一單位**偵獲即可射擊。
- 裁示 58：完全未偵獲者不得射擊，**本引擎無盲目彈幕／攔阻射擊**。

兩者相乘 → **打掉對方的觀測單位，等於讓其砲兵在師級視距（白天 3 格）之外失能。**
Run 5 紅軍 237 分全部來自這個機制的正確運用（把偵察隊釘在原地當觀測員，
讓後方推進中的師砲擊自己看不見的目標）。

已知缺陷：史實上 1944 年砲兵確實會對疑似位置實施攔阻與擾亂射擊，本引擎沒有。
待決修法：加入對格面射擊，效果按該格是否真有目標折算。

## 9.4 射程與機動的比例使開局幾何幾乎不可修正

全局白天 19 小時 × 步兵 0.67 格/hr ≈ **12 格**（一個師整局能走的總距離）。
砲兵射程 4–5 格。因此「防線設在哪一格」在尚未偵獲任何敵人的 T0–T4 就實質定案。

Run 5 敗方在 T6 才算出「我的砲兵打不到他停的那條線」，但剩餘白天只夠補回三分之一。

這在史實上合理（戰役部署確實不可逆），但它使本劇本獎勵**開局的幾何推算**
而非局中應變。待決：若希望局中判斷有更多權重，需調整機動速度與射程的比例。

## 9.5 工事分級（Run 5 新增）已驗證有效，但「移動即棄工事」讓調整陣地極貴

分級（無 0.70／淺掘 0.5hr → 0.40／散兵壕 3hr → 0.18／有頂蓋 8hr → 0.10）
搭配森林 ×0.7 相乘，使 Run 5 藍軍九個師級與營級編隊**全局零傷亡**。

這個取捨是刻意的且雙方對稱，暫不修改，但須記得它與 9.4 相乘會進一步鎖死開局決定。

## §十 Run 6 待決議題：工事沒有 hex 記憶（2026-08-02）

### 現象

`fortification` / `dig_hours` / `camo_hours` 全部是 `units[uid]` 的欄位，
state 裡**沒有任何 hex 層級的工事資料**。`advance()` 一律呼叫 `abandon_works()`。

Run 6 的藍軍指揮官在同一局內連續兩次撞到這個缺陷的兩面：

1. **不能預挖給別人**：想把工兵營前置到後方 x=7 構築陣地供主力日後進駐——做不到，
   工兵挖的洞只保護工兵營自己。
2. **不能留給自己回頭用**：BLU-3 因應變後撤離開 (9,14)，其累積 8 工時的有頂蓋工事歸零；
   即使原路走回 (9,14)，`dig_hours` 仍是 0，得從頭再挖八小時。

第 2 點明顯違反物理直覺——坑不會因為你走開就自己填平。

### 為何 Run 6 不改

手冊 §11 明文規定「移動或潰散即棄工事，挖好的洞帶不走」，是 T0 凍結的**既有規則**，
非空白。且雙方於 Run 6 T5 均已據此規則做出不可逆決策
（紅軍三個編隊放棄累積 8 工時的有頂蓋工事轉入攻勢）。
局中改之即為溯及既往，違反 `law_of_war.md` §0.1 與 §0.4。

**與裁示 17（偽裝作業）的分野**：偽裝在規則中是**空白**，填補空白屬裁判職權；
本項是規則中的**明文**，推翻明文屬修法，只能在兩局之間為之。此一分野應寫進 Run 7 手冊。

### Run 7 的建議設計

新增 hex 層級的工事記憶：

```python
state["works"] = { "x,y": {"dig_hours": float, "by": side} }
```

- `dig()` 同時累加至單位與該 hex。
- 單位進駐某 hex 時，**繼承該 hex 已有的工時**（可設上限或折損，例如未維護則每 tick 衰減）。
- 敵方佔領該 hex 者是否可用其工事？建議**可用但打折**（現成的掩體對誰都是掩體，
  但射向與交通壕方向是反的）。
- 由此，工兵前置構築陣地才有意義，1.5× 挖掘速率才有戰術價值。
- 亦須同時決定：偽裝（`camo_hours`）是否同樣具 hex 記憶。建議**否**——
  帆布與偽裝網是隨隊裝備，帶得走也帶得壞，與土工作業性質不同。

### 附帶待決

- 起步未滿一格即歸零：Run 6 中 BLU-3 於 gh34 移動進度僅 0.74（未離開該格）
  工事已歸零。現行邏輯為「呼叫移動即拔營」。若 Run 7 引進 hex 記憶，此項自動失去重要性；

## §十一 Run 6 待決議題：反砲兵測距與傷害公式的資訊對稱（2026-08-02）

### 三個相關聯的問題

**(甲) 裁示 25 排除距離，理由可能過嚴。**
裁示 25（落彈分析）給方位與口徑、不給距離，理由是「聲測與閃光交會需觀測營編制，
雙方 ORBAT 皆無」。但**閃光到聲響的時間差測距**（flash-to-bang）不需要觀測營——
一名軍官加一支碼錶即可，夜間砲口焰在 8-10km 清晰可見。裁判在 Run 6 低估了這點。
Run 7 應考慮給予**粗略距離帶**（例如「近／中／最大射程附近」三級），
或直接以 flash-to-bang 給出 ±1 格的距離估計，並區分晝夜（夜間更準）。

**(乙) 戰報的火力細節只送給開火方。**
`bombard()` 的明細字串（含**距離**、發數、每發殺傷力）進入開火方的日誌，
目標方只收到「傷亡 N 人」。這個不對稱本身合理（開火方知道自己打了多遠），
但它使「目標方能否推知距離」完全取決於裁示 25 給不給——沒有第二條路。
Run 7 若引進 (甲) 的距離帶，此項自然緩解。

**(丙) 傷害公式的常數未公布，使玩家無法自行驗算。**
手冊 §8 公布了射程與「每發 0.21 人、工事內 ×0.1」，但**未公布**
每次火力任務的發數（`FIRE_MINUTES=10` × 各砲射速）、`density_factor` 分級、
以及「>0.8×最大射程殺傷力減半」（後者裁判在 Run 6 中途以《裁判解讀》分別補送兩方）。
於是玩家無法從自身傷亡反算任何東西。

**Run 7 的選擇是二擇一，不能兩者都要**：
1. **全部公布**：手冊在 T0 即載明完整傷害公式與所有常數。
   代價是目標方可從自身傷亡反算敵砲距離——等於 (甲) 自動實現。
2. **全部不公布**：連射程與每發殺傷力也移出手冊，玩家只能靠實測累積經驗。
   代價是失去「零擲骰、可自行驗算」的設計優點。

Run 6 的現況是「公布一半」，那是最糟的組合：既不夠算，又留下裁判必須臨場補送的缺口。
裁判建議取 **1（全部公布）**，並同時實作 (甲) 的距離帶——資訊透明與現實能力兩者一致。

### 本局為何不改

裁示 25 於 T7 下令期間發布後**一則訊息內**，即有一方提問，
其答案（是否減半）足以將其攻擊目標的候選格砍半，並可能決定勝負。
裁判當場拒答並拒絕公布公式常數，理由：
- 距離為裁示 25 明文排除之項，且**不在該方戰報中**；
  裁判於對話中告知等同手寫單方內容（Run 5 洩漏管道 #2，已列硬規則）。
- 在一方提問、且足以決定勝負的時點推翻自己數分鐘前發布的裁示，
  無論物理論證多合理，都會使裁判的裁示失去可預期性。
- `law_of_war.md` §0.4：規則修訂只能在兩局之間。

**此一取捨應寫進 Run 7 手冊的裁判守則**：
裁判可以承認自己的裁示不夠好，但**不得在局中因一方請求而改之**；
正確的處理是拒答、記入本文件、下一局修正。

## §十二 Run 6 程序瑕疵：裁判在看到結果後才做出翻盤裁示（2026-08-02）

### 事件

Run 6 終局（T8）解算後，裁判連續三次修正，計分變化如下：

| 階段 | 藍 | 紅 | 性質 |
|---|---|---|---|
| 首次解算 | 2154 | **2449** | — |
| 修正 A：自走砲營閒置 | 2442 | **2449** | 純腳本 bug（友軍誤擊防護把近戰格「挑完再否決」而非「挑選前排除」，致 54 門砲閒置 3 小時） |
| **修正 B：裁示 32** | **3061** | 2292 | **在看到雙方僅差 7 分之後才作成** |

裁示 32 的內容：手冊 §7 之「從行軍中接戰 該方 ×0.7」係**逐小時的戰術狀態**
（與突襲、預設陣地、被動應戰、突破後追擊並列），判準為該編隊**該小時是否移動過**；
陷入近戰第二、三小時而未移動者不適用。原腳本將其當作整場交戰的持久標籤，套用三小時。

### 為何裁判仍採用該修正

該項屬**執行錯誤**（把逐時狀態誤用為持久標籤）而非新規則，與修正 A 同類。
明知解算有誤仍發布，比程序瑕疵更嚴重。

### 但程序瑕疵是真的，且必須記錄

**裁判的稽核努力是不對稱的**：正因首次結果僅差 7 分，裁判才繼續深挖；
若首次結果即為一方大勝，該錯誤極可能不會被發現。
這使「修正的方向」與「當時誰落後」之間存在無法排除的相關性。

裁判事後補做了反方向稽核（尋找對紅軍不利之錯誤），結果為：
- BLU-2 全程砲擊近戰格（己方裝甲師在該格內）——引擎只打指定編隊、不模擬濺射，
  紅軍砲群同樣射擊該格，**雙方對稱**，屬引擎限制而非錯誤。
- RED-AD 判為「被動應戰 ×0.85」持續三小時——源自其自身命令「停止一切行軍與攻勢、
  原地分散隱蔽」，該狀態確實持續，判定正確。
- 紅軍應變 1 之改打目標採「距其砲群最近之裝甲／砲兵」，符合其命令所列優先序。

未發現對紅軍不利之錯誤。但「事後補做」本身不能消除稽核順序造成的偏差。

### Run 7 的制度性修正建議

1. **解算與稽核分離**：tick 腳本寫完後，**先跑一次完整的自我稽核清單**
   （每個編隊每小時是否依命令行動、每個戰術狀態是否逐時判定、每個火力任務是否有目標），
   **稽核通過才印出計分**。裁判不得在看到計分後才開始找錯。
2. **戰術狀態一律逐時判定**：把裁示 32 寫進手冊 §7，並在 `battle()` 內部
   直接依 `flags["moved"]` 判定 `atk_from_march`，不交由 tick 腳本傳參——
   移除裁判裁量的空間。
3. **friendly-fire**：`bombard`／`bombard_hex` 對含有我方編隊之格射擊時，
   應對我方編隊亦施加損失（引擎現在完全不模擬）。Run 6 雙方都對近戰格開火而無代價。
4. **兵種協同的計算基礎**應寫進手冊：現行 `arms_present` 依**編制內營種**計算，
   與該編隊當前是否持有火砲無關。Run 6 裁判曾就此向一方提供錯誤資訊
   （稱抽離砲兵後協同降為 1.0，實際仍為 1.5），已於終局更正。

## §十三 Run 7 已定案：工事的 hex 記憶（2026-08-02，取代 §十之待決）

`precedents.md` §十所提之待決議題已於本次兩局之間定案並實作。

### 資料結構

```python
state["works"] = { "11,9": {"man_hours": float, "by": "allies"} }
```

**累計的是「工時 × 人數」而非「小時」。** 這是本次設計的核心判斷：
若只記小時，一個 550 人的工兵營挖 8 小時，一個 14,030 人的師進駐即白得一個有頂蓋——
但那個營挖的是 550 人份的散兵坑，容不下一個師。

```
挖掘：man_hours += 人數 × 時數 × DIG_RATE[兵種]
判級：該編隊工事級 = fort_from_hours(該格 man_hours ÷ 該編隊人數)
```

**與 Run 6 行為的相容性**：一個師自己挖 8 小時 → 人數 × 8 ÷ 人數 = 8.0 hr/人 → 有頂蓋。
與舊行為完全一致，不改變任何既有平衡。回歸測試全數通過。

### 定案的三項取捨（由 Run 6 勝方指揮官裁定）

| 議題 | 裁定 | 效果 |
|---|---|---|
| 敵方佔領後可否取用 | **完整接收，不打折** | 攻下敵方陣地即得其完整工事，「奪取陣地」的戰術價值大幅提高 |
| 近戰是否摧毀工事 | **是，但量遠小於砲擊** | `man_hours × 攻方戰力損失% × MELEE_WORKS_MULT(3.0)` |
| 摧毀係數 K | **22.6 man-hr／殺傷單位** | 見下表校準 |

### 校準（對 14,030 人之師）

| 砲群 | 每小時削減 | 有頂蓋→散兵壕 | →淺掘下限 |
|---|---|---|---|
| 單一步兵師砲兵（48 門） | 0.59 hr/人 | 8.4 小時 | 12.6 小時 |
| 兩個師的砲兵集中（96 門） | 1.19 hr/人 | 4.2 小時 | 6.3 小時 |

節奏依據：史實上的砲兵準備射擊以「小時到半天」為單位，非分鐘。

**下限＝佔用編隊之淺掘級（0.5 hr/人）。** 理由：被翻犁過的陣地不會變成平地，
會變成一片彈坑，而彈坑本身即掩體。此下限使「砲擊全滅工事」這種不寫實的結果不可能發生。

### 三項可驗證的行為改變

1. **離開再回來，洞還在。** Run 6 的主要痛點（BLU-3 為應變後撤而丟掉 8 工時有頂蓋，
   即使原路走回也須從頭再挖八小時）已消除。
2. **工兵預挖給師用仍然幾乎無效**——700 人挖 8 小時 = 8,400 man-hr，
   對一個 14,030 人的師僅 0.60 hr/人（淺掘）。**這次是因為物理，不是因為引擎偷懶。**
   工兵在史實上構築的是掩體、障礙、雷區等單點工程，不是師級散兵坑線。
3. **砲兵準備射擊成為有意義的戰術動作。** Run 6 中工事是無敵的——挖好即永遠 0.10；
   現在集中兩個師的砲兵四小時可將有頂蓋削成散兵壕，攻堅節奏因此成立。

### 未採用

**偽裝（camo_hours）不給 hex 記憶。** 帆布、偽裝網是隨隊裝備，帶得走也帶得壞，
與土工作業性質不同。移動即真正歸零，維持 Run 6 之裁示 17。

**衰減未實作。** 一局僅 54 小時，壕溝崩塌所需時間遠長於此。
若 Run 7 改為多日劇本，應重新考慮。
