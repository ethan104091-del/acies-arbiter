# 判例表 Precedents — 純戰場 The Open Field

> **這份檔案跨對局累積。** 裁判每次替一個新姿態／新編成／新戰術裁定係數，就寫一筆進來。
> 之後**任何一方**出現類似情境，必須沿用同一筆；要改判必須寫明「為什麼這次不同」。
>
> 判例不是把可能性列舉完，是把**判斷過程留下痕跡**。指揮官下了裁判沒想過的陣型時，
> 裁判當場判它自己的值——可以落在所有現有判例之外——但判完就 binding。

## 〇、不可變動的部分

### 尺度的意義（這把尺不能動，動了就沒有東西可以比較）

**砲擊暴露係數**：`1.0` ＝開闊地行軍縱隊、完全暴露　↔　`0.03` ＝地堡
**兵力比 → 損失**：`combat_v1.md` §III 對照表，一行不改
**戰鬥力 CP 的九個因子**：`combat_v1.md` §II，因子清單不變（各因子的**值**才是判例的範圍）

### 裁定時點（最重要的一條）

```
指揮官在命令裡描述姿態
   ↓
裁判當場裁定係數 ＋ 寫下依據 → 同時公告雙方 → 寫進本表
   ↓  ← 此時裁判還不知道誰會被打、打多重
進入解算（引擎照該係數執行，不再重判）
```

**在這個順序下，裁判不可能挑一個對誰有利的數字，因為判的時候還不知道誰會受益。**

若情況是解算中途才浮現（沒人宣告但事實發生），裁判當場判、立即公告，並**必須同時寫明此判決對哪一方有利**。

### 指揮官的主張權

指揮官可以在命令裡主張：「我這個部署應該算 X，理由是 Y」。裁判裁定後公告雙方，成為新判例。
（Run 4 藍軍全局提出 30 餘個規則問題、產生 45 條裁示，是本制度的雛形。）

## 二、彈著覆蓋與密度判例

**Run 4 的做法有結構性錯誤，已廢止**：當時用單一「密度係數」同時代表「目標本身多疏」與
「目標有多少落在彈著區內」，並依**兵力**分級（師 0.20／旅 0.15／營 0.30／小單位 0.12）。

**改正後的形式**：
```
傷亡 = 發數 × 每發殺傷力
       × 彈著區對目標的覆蓋率   ← 判例（看指揮官描述的疏開程度與彈著散布）
       × 該處防護（暴露係數）
```
一個 hex ＝ 2km × 2km ＝ **4 km²**；一次集中射擊的彈著散布約 200×200m ~ 500×500m
＝ **0.04–0.25 km²，佔格子面積的 1–6%**。覆蓋率必須反映這個量級。

## 三、砲擊殺戰車判例 ★Run 4 最大的錯誤

`determinism_v1` §III 原文：「100 發 105mm vs **100m 內**開闊戰車 = 0.5 輛/百發」→ 0.005/發。
**限定詞是「彈著點 100m 內」。** Run 4 把它套在整個 2km 格子的編隊上、每一發都算，
等於假設每發砲彈都落在戰車旁邊。

後果：全場 128 輛戰車損失中 **83 輛（65%）死於砲擊**；藍軍 8,813 分中 **2,280 分（26%）來自戰車**。
歷史上（諾曼第 ORS 調查）砲兵**直接擊毀**戰車的比例極低，主要價值是壓制與癱瘓機動。

**連鎖後果（比數字本身更嚴重）**：
> 砲兵隔 4 格穩定殺戰車、零風險；戰車要互射得進到 1 格、還吃攻擊 ×0.7。
> → 理性的裝甲師永遠不該前進 → **Run 4 全局戰車對戰車直射交戰 0 次**
> → `determinism_v1` §I 命中係數表、`combat_v1` §IV 穿甲表——規則書最精細的兩個系統——**一次都沒用到**。

| # | 情境 | 判法 | 依據 |
|---|---|---|---|
| T1 | 戰車在彈著點 100m 內、開闊 | 0.005/發（105）、0.02/發（155） | `determinism_v1` §III 原文 |
| T2 | 戰車散佈於 2km 格內、砲擊該格 | **待判**：須先乘「彈著區覆蓋率」（見二） | Run 4 錯在跳過這一步 |

## 八、經驗與命中 ★結構性修正（Run 4 之後定案）

### 問題

Run 4（與規則書原狀）的結構缺陷：**只有戰車有「命中」這個環節。**

```
戰車（determinism_v1 §I）：命中數 = 發數 × 命中係數 × 修正（距離/天氣/**經驗**/疲勞）→ 穿甲表
砲兵（determinism_v1 §III）：傷亡 = 發數 × 每發殺傷力 × 暴露 × 密度     ← 無命中環節
步兵（combat_v1 §II）：      CP 九因子相乘                              ← 經驗壓成籠統乘數
```

「每發殺傷力 0.30 人/發」是**命中率與單發威力被揉在一起**的數字，揉在一起經驗就無處可進。
後果：Run 4 中特戰旅的 ⭐⭐⭐⭐⭐ 只在唯一一場地面戰生效過一次，其餘 7 個 tick 完全沒作用。

### 定案的形狀（把戰車的形狀推廣到所有兵種）

```
效果 = 發數 × 命中／有效彈率 × 單發效果 × 目標防護
                  ↑ 經驗在這裡，而且只在這裡
```

| 兵種 | 「命中」的實際內容 |
|---|---|
| 步兵 | 有效射擊比例、火力紀律（新兵打高、老兵等目標進有效距離） |
| 砲兵（間瞄） | **觀測員修正射效率 ＋ 砲班散布圈**（老 FO 兩次修正跨叉，新 FO 六次還在浪費彈） |
| 戰車（直瞄） | 規則書已有：⭐ 0.70 / ⭐⭐ 0.85 / ⭐⭐⭐ 1.00 / ⭐⭐⭐⭐ 1.05 / ⭐⭐⭐⭐⭐ 1.10 |
| 偵察 | 回報正確率（番號、數量、座標精度） |

### 不可重複計算：經驗有兩個入口，互不重疊

| 入口 | 代表什麼 | 用在哪 |
|---|---|---|
| **CP 乘數 0.75–1.30**（`combat_v1` §II，規則書既有） | 戰術素養與凝聚力 | 地面戰（近接/突擊/守備）——此處不計發數 |
| **命中率**（本次新增） | 射擊技術與觀測品質 | 所有**計算發數**的射擊：步兵火力、砲兵、戰車、迫砲 |

兩者不重疊，因為地面戰 CP 公式裡沒有「發數」這個量。

| # | 待判項目 | 已知參考 |
|---|---|---|
| X1 | **間瞄砲兵的經驗帶寬** | 規則書給直瞄戰車 ±10%；但歷史上間瞄的 FO/FDC 訓練差距遠大於此（老 FO 與新 FO 的耗彈量可差 2-3 倍）。帶寬應寬於 ±10%，具體值待判 |
| X2 | 步兵火力的有效射擊比例隨經驗如何變 | |
| X3 | 觀測品質對砲擊的影響（FO 修正射 vs 地圖射擊 vs 無觀測） | `combat_v1` §VI 有時序（呼叫後 3-7 分開火、精度誤差 50-75m），無係數 |

### 部隊素質退化（引擎該記帳的部分）★裁判曾判錯，此為更正版

**錯誤版本（已廢止）**：「老兵先死，傷亡按老兵優先扣減」。

**文獻方向相反：新兵/補充兵的傷亡率明顯高於老兵。** 二戰歐陸的個別補充兵制度出名的問題就是——
補充兵被單獨塞進正在接觸的部隊，班長還沒記住他的名字，他就：散兵坑挖太淺、聽不出彈道該趴時在跑、
遭火力時擠成一團、不知道自己班的火力配置與撤退路線。他在加入後**頭幾天**的傷亡率遠高於老兵；
老兵活下來正是因為已經學會這些。

**唯一「先死」的是幹部**：班長、排長、連長因為要指揮、要暴露、要帶頭，傷亡確實不成比例集中。
但其意義不是「老兵被消耗掉」，而是**部隊失去了傳遞經驗的管道**。

**正確的退化機制（三個來源）**
1. 補充兵大量湧入 → 稀釋 `veteran_fraction`
2. 幹部傷亡 → 經驗傳遞中斷，剩餘老兵的經驗無法擴散到新兵
3. 建制凝聚力被打散 → 班排的默契重建需要時間

**關鍵推論**：一個被打殘的師**補滿員之後不是復原，是變成一個更容易崩的師**——
因為新補進來的那批接下來會死得更快，形成複利式衰退。

Run 4 實例：RED-1 損失 3,024 人（22%），XP 從頭到尾維持 3。
若有此機制，它補充後的下一個 tick 會**比補充前更糟**：命中率下降 → 砲兵輸出下降 → 傷亡再上升。

**引擎該記的帳**：`veteran_fraction`（老兵佔比）、`cadre_fraction`（幹部佔比）、補充兵到位時間與數量；
傷亡分配時**新兵承受的比例高於其人數佔比**（具體倍率待裁定）。48 小時內經驗不會上升，但稀釋是立即的。

## 9.1 ★ W1 的要件 C 有兩個獨立的缺陷（本局最重要的產出）

W1「攻擊已喪失戰鬥力之編隊」要求三要件同時成立，其中
**要件 C：無脫離能力＝補給走廊切斷**。

### 缺陷一（裁判自己的認定）：C 把兩件不等價的事綁在一起

測試案例：藍軍 BLU-3-rcn 終局 **兵力 124/300（傷亡 58.7%）、組織度 2.0、
火砲 0、戰車 0、全局五十四小時從未開火**，承受十二小時集中砲擊。

- 要件 A 成立（傷亡 ≥50% 且 org ≤25）
- 要件 B 成立（未攻擊、火砲存量 0）
- **要件 C 不成立**（補給走廊全程 intact）

→ W1 不成立。**在任何常識判斷下該編隊早已喪失戰鬥力，但規則說沒有。**
「無法脫離」與「無法作戰」是兩件事，C 把後者的判定綁在前者上。

### 缺陷二（敗方在覆盤中提出，比缺陷一更嚴重）

裁示 43 自行公開過：`compute_supply` **不為抽離的營級單位計算走廊**
（`if u.get("is_detachment"): continue`），故抽離單位的補給狀態多數情況沿用「完整」。

與要件 C 相乘的結果是：

> **任何營級單位都不可能滿足 W1，無論它被摧毀得多徹底。**

「禁止在屍體上收割殺傷分數」這條禁令，恰好對**最容易變成屍體的那一類單位**失效。

（敗方同時誠實註記：本案即使逐格計算，C 也會因事實而不成立
——紅軍從未進入 row 11 的 x ≤ 13。所以這是制度缺口，不是該方在本案的冤屈。）

### 待決修法（Run 6 前擇一或並行）

1. 為抽離的營級單位計算補給走廊（修 `compute_supply`）。
2. 要件 C 改為「無法脫離**或**無法作戰」（把 and 改成 or）。
3. 對某一規模以下的單位，C 改為可操作的判準：
   殘餘移動率低於攻擊方，或處於攻擊方火力範圍內且無脫離路徑。
4. 另立一條獨立禁令：對已無任何武器、且持續不還擊之編隊的持續砲擊。

**注意時序紀律**：本局已於 T0 凍結規則，故不得依此改判 Run 5。

## 9.2 前進指揮所缺少「必須在前」的檢查

`command.delay_tier_adjust` 只檢查「軍長是否駐前進指揮所」與「距離是否 ≤ FWD_RANGE」，

## 9.3 觀測即開火權（裁示 56＋58）是一組極強的機制

## §十一 Run 6 待決議題：反砲兵測距與傷害公式的資訊對稱（2026-08-02）

### 三個相關聯的問題

**(甲) 裁示 25 排除距離，理由可能過嚴。**
裁示 25（落彈分析）給方位與口徑、不給距離，理由是「聲測與閃光交會需觀測營編制，
雙方 ORBAT 皆無」。但**閃光到聲響的時間差測距**（flash-to-bang）不需要觀測營——
一名軍官加一支碼錶即可，夜間砲口焰在 8-10km 清晰可見。裁判在 Run 6 低估了這點。
Run 7 應考慮給予**粗略距離帶**（例如「近／中／最大射程附近」三級），
或直接以 flash-to-bang 給出 ±1 格的距離估計，並區分晝夜（夜間更準）。

**(乙) 戰報的火力細節只送給開火方。**
`bombard()` 的明細字串（含**距離**、發數、每發殺傷力）進入開火方的日誌，
目標方只收到「傷亡 N 人」。這個不對稱本身合理（開火方知道自己打了多遠），
但它使「目標方能否推知距離」完全取決於裁示 25 給不給——沒有第二條路。
Run 7 若引進 (甲) 的距離帶，此項自然緩解。

**(丙) 傷害公式的常數未公布，使玩家無法自行驗算。**
手冊 §8 公布了射程與「每發 0.21 人、工事內 ×0.1」，但**未公布**
每次火力任務的發數（`FIRE_MINUTES=10` × 各砲射速）、`density_factor` 分級、
以及「>0.8×最大射程殺傷力減半」（後者裁判在 Run 6 中途以《裁判解讀》分別補送兩方）。
於是玩家無法從自身傷亡反算任何東西。

**Run 7 的選擇是二擇一，不能兩者都要**：
1. **全部公布**：手冊在 T0 即載明完整傷害公式與所有常數。
   代價是目標方可從自身傷亡反算敵砲距離——等於 (甲) 自動實現。
2. **全部不公布**：連射程與每發殺傷力也移出手冊，玩家只能靠實測累積經驗。
   代價是失去「零擲骰、可自行驗算」的設計優點。

Run 6 的現況是「公布一半」，那是最糟的組合：既不夠算，又留下裁判必須臨場補送的缺口。
裁判建議取 **1（全部公布）**，並同時實作 (甲) 的距離帶——資訊透明與現實能力兩者一致。

### 本局為何不改

其答案（是否減半）足以將其攻擊目標的候選格砍半，並可能決定勝負。

- 距離為裁示 25 明文排除之項，且**不在該方戰報中**；
  裁判於對話中告知等同手寫單方內容（Run 5 洩漏管道 #2，已列硬規則）。
- 在一方提問、且足以決定勝負的時點推翻自己數分鐘前發布的裁示，
  無論物理論證多合理，都會使裁判的裁示失去可預期性。
- `law_of_war.md` §0.4：規則修訂只能在兩局之間。

**此一取捨應寫進 Run 7 手冊的裁判守則**：
裁判可以承認自己的裁示不夠好，但**不得在局中因一方請求而改之**；

### 事件

Run 6 終局（T8）解算後，裁判連續三次修正，計分變化如下：

| 階段 | 藍 | 紅 | 性質 |
|---|---|---|---|
| 首次解算 | 2154 | **2449** | — |
| 修正 A：自走砲營閒置 | 2442 | **2449** | 純腳本 bug（友軍誤擊防護把近戰格「挑完再否決」而非「挑選前排除」，致 54 門砲閒置 3 小時） |

裁示 32 的內容：手冊 §7 之「從行軍中接戰 該方 ×0.7」係**逐小時的戰術狀態**

### 為何裁判仍採用該修正

該項屬**執行錯誤**（把逐時狀態誤用為持久標籤）而非新規則，與修正 A 同類。
明知解算有誤仍發布，比程序瑕疵更嚴重。

### 但程序瑕疵是真的，且必須記錄

**裁判的稽核努力是不對稱的**：正因首次結果僅差 7 分，裁判才繼續深挖；
若首次結果即為一方大勝，該錯誤極可能不會被發現。
這使「修正的方向」與「當時誰落後」之間存在無法排除的相關性。

- BLU-2 全程砲擊近戰格（己方裝甲師在該格內）——引擎只打指定編隊、不模擬濺射，
  紅軍砲群同樣射擊該格，**雙方對稱**，屬引擎限制而非錯誤。
- RED-AD 判為「被動應戰 ×0.85」持續三小時——源自其自身命令「停止一切行軍與攻勢、
  原地分散隱蔽」，該狀態確實持續，判定正確。
- 紅軍應變 1 之改打目標採「距其砲群最近之裝甲／砲兵」，符合其命令所列優先序。

未發現對紅軍不利之錯誤。但「事後補做」本身不能消除稽核順序造成的偏差。

### Run 7 的制度性修正建議

1. **解算與稽核分離**：tick 腳本寫完後，**先跑一次完整的自我稽核清單**
   （每個編隊每小時是否依命令行動、每個戰術狀態是否逐時判定、每個火力任務是否有目標），

2. **戰術狀態一律逐時判定**：把裁示 32 寫進手冊 §7，並在 `battle()` 內部
   直接依 `flags["moved"]` 判定 `atk_from_march`，不交由 tick 腳本傳參——
   移除裁判裁量的空間。
3. **friendly-fire**：`bombard`／`bombard_hex` 對含有我方編隊之格射擊時，

4. **兵種協同的計算基礎**應寫進手冊：現行 `arms_present` 依**編制內營種**計算，

   （稱抽離砲兵後協同降為 1.0，實際仍為 1.5），已於終局更正。

## §十三 Run 7 已定案：工事的 hex 記憶（2026-08-02，取代 §十之待決）

`precedents.md` §十所提之待決議題已於本次兩局之間定案並實作。

### 資料結構

```python
state["works"] = { "11,9": {"man_hours": float, "by": "allies"} }
```

**累計的是「工時 × 人數」而非「小時」。** 這是本次設計的核心判斷：
若只記小時，一個 550 人的工兵營挖 8 小時，一個 14,030 人的師進駐即白得一個有頂蓋——
但那個營挖的是 550 人份的散兵坑，容不下一個師。

```
挖掘：man_hours += 人數 × 時數 × DIG_RATE[兵種]
判級：該編隊工事級 = fort_from_hours(該格 man_hours ÷ 該編隊人數)
```

**與 Run 6 行為的相容性**：一個師自己挖 8 小時 → 人數 × 8 ÷ 人數 = 8.0 hr/人 → 有頂蓋。
與舊行為完全一致，不改變任何既有平衡。回歸測試全數通過。

### 定案的三項取捨（由 Run 6 勝方指揮官裁定）

| 議題 | 裁定 | 效果 |
|---|---|---|
| 敵方佔領後可否取用 | **完整接收，不打折** | 攻下敵方陣地即得其完整工事，「奪取陣地」的戰術價值大幅提高 |
| 近戰是否摧毀工事 | **是，但量遠小於砲擊** | `man_hours × 攻方戰力損失% × MELEE_WORKS_MULT(3.0)` |
| 摧毀係數 K | **22.6 man-hr／殺傷單位** | 見下表校準 |

### 校準（對 14,030 人之師）

| 砲群 | 每小時削減 | 有頂蓋→散兵壕 | →淺掘下限 |
|---|---|---|---|
| 單一步兵師砲兵（48 門） | 0.59 hr/人 | 8.4 小時 | 12.6 小時 |
| 兩個師的砲兵集中（96 門） | 1.19 hr/人 | 4.2 小時 | 6.3 小時 |

節奏依據：史實上的砲兵準備射擊以「小時到半天」為單位，非分鐘。

**下限＝佔用編隊之淺掘級（0.5 hr/人）。** 理由：被翻犁過的陣地不會變成平地，
會變成一片彈坑，而彈坑本身即掩體。此下限使「砲擊全滅工事」這種不寫實的結果不可能發生。

### 三項可驗證的行為改變

1. **離開再回來，洞還在。** Run 6 的主要痛點（BLU-3 為應變後撤而丟掉 8 工時有頂蓋，
   即使原路走回也須從頭再挖八小時）已消除。
2. **工兵預挖給師用仍然幾乎無效**——700 人挖 8 小時 = 8,400 man-hr，
   對一個 14,030 人的師僅 0.60 hr/人（淺掘）。**這次是因為物理，不是因為引擎偷懶。**
   工兵在史實上構築的是掩體、障礙、雷區等單點工程，不是師級散兵坑線。
3. **砲兵準備射擊成為有意義的戰術動作。** Run 6 中工事是無敵的——挖好即永遠 0.10；
   現在集中兩個師的砲兵四小時可將有頂蓋削成散兵壕，攻堅節奏因此成立。

### 未採用

**偽裝（camo_hours）不給 hex 記憶。** 帆布、偽裝網是隨隊裝備，帶得走也帶得壞，
與土工作業性質不同。移動即真正歸零，維持 Run 6 之裁示 17。

**衰減未實作。** 一局僅 54 小時，壕溝崩塌所需時間遠長於此。
若 Run 7 改為多日劇本，應重新考慮。

```
每 tick 補給   +22%（POL/SA/HE/AT/RAT）
最重的 L3 消耗  每 tick 15%（POL）、9%（HE 砲彈）
                 ↑ 補給永遠大於消耗
```

Run 6 打完 54 小時，雙方**砲彈仍剩 91–96%**，全局最低單一資源是 RED-AD 的 POL 22.3%
（那是走路走掉的）。於是整條鏈斷掉：

> 彈藥打不完 → 補給無所謂 → 沒人有理由深入敵後切走廊
> → W1 要件 C 永不成立 → 戰爭法連續兩局零觸發

**所以修戰爭法要從彈藥下手，不是從法條下手。**

### 定案：彈藥以實數發數計

基數取自 `rules/forces_v1.md` 的開戰時彈藥表（`AMMO_LOAD`）：

| 編隊 | 火砲 | 每次任務 | 基數 | 可連續射擊 |
|---|---|---|---|---|
| 步兵師 | 105mm×36 | 900 發 | **5,800** | 6.4 小時 |
| 步兵師 | 155mm×12 | 180 發 | **1,400** | 7.8 小時 |
| 裝甲師 | SP105×54 | 1,350 發 | **6,500** | 4.8 小時 |
| 特戰旅 | 81mm×12 | 480 發 | **3,500** | 7.3 小時 |

**一個基數約等於一個 tick 的連續射擊**——這正是史實上「一個基數」的意義。

補給率 **基數的 40%／tick**（走廊完整；受威脅半量、切斷為零），
依 `rules/logistics_v1.md`「彈藥車隊 SA+HE+AT 共 40%／趟」。
連續射擊一個 tick 即見底，補給追不上——指揮官必須挑時機開火。

抽離營的彈藥**依火砲比例自母編隊守恆分割**，與裝備守恆同一套機制。

### 定案：火力任務三分類，每類各有獨占優勢

**首次實作的版本是退化的**，記錄於此作為設計教訓：

原核可的倍率（急襲 彈0.3/效0.4、壓制 1.0/1.0、干擾 彈1.5/效0.5）是**純懲罰**，
量測結果為效率 18.5／47.2／23.5——**壓制在每個維度都最好，干擾被完全支配**，
沒有任何情況下選它是合理的。

**純懲罰的倍率必然使選項退化。每一種任務要存在，就得有一件別人做不到的事。**

修正後：

| 任務 | 佔用 | 彈量× | 每發殺傷× | 獨占優勢 | 實測 |
|---|---|---|---|---|---|
| **急襲**（TOT） | 3 min | 0.4 | **1.5** | 效率最高、一個基數撐 16 小時 | 傷亡 30／耗彈 432／效率 69 |
| **壓制** | 10 min | 1.0 | 1.0 | 絕對傷亡最高 | 傷亡 51／耗彈 1,080／效率 47 |
| **干擾** | 30 min | 0.4 | 0.3 | **該小時凍結目標的土工作業與休整** | 傷亡 6／耗彈 432／效率 14 |

史實依據：1944 年發展 TOT（Time on Target）正是為了讓全部彈著同時落地、
使目標來不及進洞，故其每發殺傷應**更高**而非更低。
干擾射擊的目的從來不是殺人，是讓對方無法工作。

**彈量倍率是「相對標準任務的總彈量」，不與佔用時長相乘**——
首次實作讓兩者相乘，造成急襲只有標準的 9%、干擾高達 450%，已修。

### 干擾射擊的價值只在工事有 hex 記憶之後才成立

六小時射擊的對照（對同一個師）：

| | 對方工事 | 對方暴露 | 自身耗彈 |
|---|---|---|---|
| 壓制 | 散兵壕 3.12 hr/人 | 0.18 | 5,400 發（見底） |
| **干擾** | **無工事 0.00** | **0.70** | 2,160 發（37%） |

用 40% 的彈藥把對方永遠釘在無工事狀態，挨打倍率放大近四倍。
**干擾射擊不殺人，它讓別人來殺。** 在 Run 6 的舊制下（工事無敵、挖好即永遠 0.10）
凍結土工作業毫無價值，這個機制要等 §十三 的 hex 記憶落地才有意義。

### 《戰爭法》W1 要件 B 修訂

要件 B 增列**「彈藥歸零」**：
「前一小時未實施任何攻擊動作，且（火砲存量 0 **或彈藥歸零** 或補給狀態 = cut）」。

**要件 C 未放寬。** Run 5 敗方曾主張放寬，被駁回，理由
「一個能撤走的單位不是屍體」——裁判接受該論證。
正確的解法是讓切補給線變得有價值，不是降低門檻。彈藥實數化正是那個解法。

### 一併修掉的兩個實作錯誤

1. **火力任務的彈量與時長重複相乘**（見上）。
2. **`detach_bn` 分割彈藥時分母重複計算**：該段執行於母編隊裝備扣除**之前**，
   `parent.equip.guns` 已是扣除前的值，卻又加了一次 `eq["guns"]`，
   使抽離營少拿彈藥（18/52 應得 2,250 發，實得 1,671）。已修，測試已覆蓋。

## §十五 裁示 34 取代裁示 25 的「一律不給距離」（2026-08-04，兩局之間）

### 為何要改：原裁示的理由不成立

Run 6 裁示 25（落彈分析）給方位與口徑但**不給距離**，理由載明為
「聲測與閃光交會需專門觀測營編制，雙方 ORBAT 皆無」。

但 `rules/combat_v1.md:498-502` 的反砲擊一節**明文列了聲測**：

```
#### 4. 反砲擊（Counter-battery）
- DF + 聲測 + 觀察機定位敵砲位
```

規格書把聲測當**標準手段**，不是特殊編制。原理由因此站不住。

更根本的是，真正可用的方法根本不是聲測交會，而是 **flash-to-bang**——
量砲口焰與聲響的時間差。一名軍官加一支碼錶即可，不需要任何編制。
裁判在 Run 6 期間即已於裁示_13 中承認此點，但**拒絕在局中因一方提問而改判**，
並將其列為兩局之間的修訂事項。本節即為該修訂。

### 定案：依晝夜給不同精度

| 時段 | 可得 | 依據 |
|---|---|---|
| **夜間／黎明** | 距離 **±1 格** | 砲口焰在 8–10 km 清晰可見 |
| **白天** | 僅**粗略距離帶**（近距 ≤2／中距 3–4／接近最大射程 ≥5） | 砲口焰幾乎看不見；改由彈著散佈判定 |

物理對照（一格 `HEX_KM = 8.5/4 ≈ 2.12` km，聲速 340 m/s）：
1 格 → 6.2 秒、2 格 → 12.5 秒、4 格 → 25.0 秒、5 格 → 31.2 秒。碼錶量得出來。

**零擲骰**：兩者皆為目標距離的確定函數。

### 產生一個機制自然推導的後果

**夜間開火比白天危險。**

白天對方只知道「正東、中距」——要覆蓋 3–4 格兩個候選；
夜間對方知道「正東、3–5 格」——三格，但精度反而更高，
且結合方位後可用兩個編隊分別覆蓋。

這不是刻意設計的平衡調整，是「夜間看得見砲口焰」這個物理事實推出來的。
Run 6 的紅軍在 gh38–41（夜間）連續砲擊四小時，若當時已有本裁示，
藍軍會拿到「正東、3–5 格」而非只有「正東」——嫌疑範圍從 5 格收斂到 3 格。

### 生效時點：Run 7 T0，不追溯

裁示 25 在 Run 6 期間曾**追溯**回填彈坑分析，理由是彈坑在被打的當下就物理存在，
事後分析是隨時可做的事。

本項不同：它是**新授予的能力**，依《戰爭法》§0.4「本文修訂只能在兩局之間進行，
且修訂後版本自下一局 T0 起生效」。

### 尚未處理：反砲兵摧毀率

`combat_v1.md:504`「每砲彈藥 30 發 → 1 門敵砲被摧毀」**從未實作**。
引擎的火砲損失走 `GUN_SPEC` 第四個係數，與該條無關。
彈藥改為實數之後（§十四），這條規則現在**有可能實作**了——
反砲兵射擊可以按消耗的發數換算敵砲損失。列為 Run 8 待決（`docs/TODO.md` P5-13）。

## §十六 傷害模型重新校準：缺陷 1、2、3、6（2026-08-04，兩局之間）

指揮官指示：「這些調整的合理性對照現實就好，參數的調整也是對其現實。」
以下每個數字都指回史實來源，不含任何平衡論證。

### 缺陷 2：覆蓋率必須是純幾何量

**發現舊值一定錯的關鍵**：引擎的「每發殺傷力 0.30 × 暴露 0.70 = **0.21**」，
恰好等於手冊 §8 的「砲擊開闊地散開步兵**每發 0.21 人**」。

也就是說 0.21 是**落在部隊之間的每一發**的殺傷力，而覆蓋率的唯一職責是把
「發射的發數」換算成「落在部隊之間的發數」——**純幾何，不該帶任何殺傷力資訊**。
舊 `density_factor` 給 0.12–0.30（依兵力），把兩件事揉在一起。

**校準錨點**：WWII 野戰砲兵持續作戰統計，**每 100–300 發造成 1 人傷亡**
（含所有落空、壓制、擾亂射擊的實戰平均）。舊值下引擎是 1 人 / 21 發，高出 5–14 倍。

推導：`覆蓋率 = 彈著區面積 ÷ 編隊佔地面積`。彈著區靜止 0.08 km²／行軍 0.25 km²
（§二）；編隊佔地依 1944 部署密度（FM 100-5）：師 4.00／旅 1.50／營 0.50／連 0.25 km²。

驗證：師・無工事・靜止 → **1 人 / 216 發**（帶內）；全軍 210 門集中 → **1 人 / 214 發**（帶內）。

### 缺陷 1：戰車那條完全沒有覆蓋率項

`determinism_v1` §III 原文的限定詞是「彈著點 **100m 內**」，引擎把它吃掉了。
戰車改用膨脹 100m 的面積（靜止 0.23／行軍 0.49 km²）。

修正後兩個師的砲兵對裝甲師一小時：靜止 **0 輛**、行軍中 **1 輛**、挖了掩壕 **0 輛**。
史實依據：諾曼第 ORS 調查——砲兵直接擊毀戰車的比例極低。

**這修掉一個退化的誘因**：Run 4 有 65% 的戰車損失死於砲擊，
砲兵隔 4 格零風險殺戰車，於是理性的裝甲師永遠不該前進，
全局戰車對戰車直射交戰 **0 次**，規則書最精細的兩個系統一次沒用到。

### T3 壓制：與缺陷 1 必須成對

`SUPPRESS_MOVE_MULT = 0.5`——前一小時遭砲擊者本小時移動速率減半。
史實依據：遭砲擊的部隊就地臥倒、疏散、後送傷員、重整隊形，該時段失去行軍節奏。
**這是砲兵在 1944 年的主要價值**，直接擊毀裝備不是。

若只拿掉砲兵的反裝甲能力而不給它壓制，砲兵就失去存在理由——兩者必須一起做。

### 缺陷 3：森林的方向本來是反的

依 §E8 已判定的倍率拆兩段：未達有頂蓋 **×1.3**（樹爆：林中引信提前起爆，
破片由上而下灑進散兵坑）、已達有頂蓋 **×0.5**。
原為一律 ×0.7——當時準則規定「**進林必挖有頂蓋掩體**」正是為此。

### 缺陷 6：經驗進命中

依 §八 明定的「兩個互不重疊的入口」，`bombard` 的每發殺傷力另乘 `VET[xp]`。
原本經驗只進地面戰 CP，使特戰旅的 ⭐⭐⭐⭐⭐ 幾乎全局無作用。

### 由此改變的整體形狀

| 一小時的產出 | 分數 |
|---|---:|
| 全軍砲兵（210 門）打無工事的師 | 22 |
| 全軍砲兵打有頂蓋的師 | 3 |
| **裝甲師近戰** | **360** |

**近戰現在比砲兵有效 16 倍。** 1944 年的消耗來自突擊而非砲擊。
砲兵回到史實職能：削工事、癱瘓機動、緩慢消耗——**為突擊做準備**。

`WORKS_DEMOLITION = 22.6` **無須重新校準**：它乘的是「殺傷單位」，
而覆蓋率是在那之後才乘的，殺傷單位的尺度沒有改變。實測仍為兩個師的砲兵 4 小時削掉有頂蓋。

### 附帶：五個測試因數字變小而失敗，全是斷言問題

重新校準把單編隊一小時的傷亡壓到個位數，**整數捨入開始主導**，
五個斷言絕對數量的測試因此失敗（機制全部仍在）。
修法是**斷言機制而非量級**、或放大樣本（多編隊同時射擊）。
這個模式（測試斷言過度指定）在本次檢討中已出現四次，值得記住。

## §十七 P5-13 反砲兵：規則書的數字是錯的（2026-08-04）

### 判定：`combat_v1.md:504` 的「每砲彈藥 30 發 → 1 門敵砲被摧毀」錯誤

30 發毀一門，意味著一個 12 門制砲兵營在**三分之一小時內全滅**，
與同一份規則書的其他數字（每 100–300 發 1 人傷亡，§十六）差三個數量級。

**它應是把制壓（neutralization）誤記為摧毀（destruction）。**
史實上反砲兵的成果是壓制砲班、迫使轉移陣地——物理摧毀火砲屬少數。

幾何估算：4 門制砲兵連約 200×200m ＝ 40,000 m²；105mm 對火砲的有效殺傷半徑約 15m
＝ 700 m²；4 門砲易損面積佔砲位 7%，其中約 20% 造成摧毀 → **每 71 發毀一門**。

### 真正的錯誤在別處：火砲被當成比戰車更硬

原式 `gun_kill = _inc[1] × texp × tcov × 0.5`——那個 **0.5 方向是反的**。

牽引火砲無裝甲，破片即可毀掉照準具、輪組、制退機；戰車需近失彈直接命中。
由有效殺傷半徑推導（戰車 5m／78 m²、牽引火砲 15m／700 m²）
→ 易損面積比 **9 倍**。故 `GUN_VS_TANK_VULN = 9.0`。

火砲另有自己的暴露表：砲坑只遮下半，且**射擊時必須露出砲身**，
故 `GUN_EXPOSURE`（1.00／0.60／0.45／0.30）全面高於戰車（1.00／0.30／0.15／0.05）。

### 但實際的限制是飽和上限，不是係數

`ecap_g = max(1, int(火砲數 × 8%))`：12 門的砲兵營 → **每小時最多 1 門**。
所以對小砲兵營，係數修正看不出效果；對 48 門的整編師（上限 3），
距 4 格的射擊由 **0 門**變為 **2 門**（無工事）／**1 門**（散兵壕）。

### 實測結果與史實一致

反砲兵打一個抽離的 12 門砲兵營，6 小時：**人員 −39%、火砲 −6/12**。

**人員損失才是主要效果**——那是一個被徹底壓制的砲兵營。這正是史實上反砲兵的樣子。

### 未實作且刻意不實作：迫使轉移陣地

史實上反砲兵最大的成果是迫使敵砲兵轉移——一旦轉移，它失去測地標定、失去砲坑，
且轉移的小時不能射擊（§VI 行軍中不得砲擊）。

**引擎不強制轉移**，因為那會是裁判代替指揮官作戰術決定（違反 §0 的最小解讀）。
指揮官可自行下令轉移；規則只保證轉移的代價與收益都如實計算。

## §十八 Run 7 程序瑕疵：裁判把單方資訊誤送給第三方 agent（2026-08-05，T0）

### 發生了什麼

Run 7 的藍軍軍長是一個名為 **BlueCommander-2** 的 agent（裁判開的）。
裁判要通知它「三條通則裁示已公告、你得修改 T0 命令」時，收件人只寫了
**`BlueCommander`**（少了 `-2`），訊息被路由到**另一個脈絡下同名的 agent**——
那是別的 session 的藍軍軍長，工作目錄在自己的 scratchpad，早已被解除職務。

那則訊息裡含有 Run 7 藍軍的**單方資訊**：營級代號、主指揮所座標 (6,4)、
四個整編編隊的目標格、以及一段關於前進指揮所中位數判準的分析。

### 為什麼沒有釀成洩漏

收件的 agent 做了三件正確的事：**核對身分不符、拒絕執行、要求裁判先確認。**
它明確指出座標與代號都不是它下過的命令、路徑不在它的授權範圍、且它已停止行動。
它**沒有**去讀那個 Desktop 目錄。

因此對局中的實質風險（紅軍得知藍軍部署）**未發生**——收件者不是紅方，
也不是 Run 7 的參與者。但這是**運氣，不是設計**。

### 這件事的性質

`dispatch.py` 的洩漏檢查只管**寫進簡報檔**的內容，管不到裁判**用訊息直接送出去**的東西。
兩條通道，只有一條有閘門。

裁示 7（對一方自身命令的解讀只回該方）在規則上是對的，但它假設「該方」這個
收件人是唯一確定的。當收件人由**名字**而非**識別碼**指定，而名字可能碰撞時，
這個假設就不成立。

### 定案

1. **對指揮官的一切單方訊息，收件人一律用該 agent 的完整名稱或識別碼**，
   不得用可能碰撞的簡稱。送出前先確認該名稱就是本局開的那一個。
2. **能寫進簡報檔的，就不要用訊息送。** 簡報檔有洩漏檢查、有歷史副本、可稽核；
   訊息沒有。訊息只用於程序通知（「裁示已公告」「可修改命令」「請確認」），
   單方事實一律走 `dispatch.py`。
3. 本次誤送的資訊已請收件方不得轉述，並確認其維持停止狀態。

### 與 §十二 的關係

§十二記的是「裁判的稽核努力不對稱」，本節記的是「裁判的**發送通道**沒有閘門」。
兩者是同一類問題的不同面向：**規則管得住引擎，管不住裁判自己的手。**
凡是裁判手動做的動作（手寫、手送、手改），都必須有一個與結果無關的機械檢查，
否則它的可靠度就等於裁判當下的注意力——而那是會波動的。

## §十九 Run 7 T0：兩處引擎行為與規則措辭不一致（2026-08-05）

由指揮官提問時查出，兩處都在 T0 解算前裁定。

### 一、有守軍的格可以用走的進去（裁示 47）

裁示 11 寫「該格**無守軍**時，敵戰鬥單位進入即判定斬首」，
但 `arbiter.plan_path` 與 `advance` **只檢查地形，完全不檢查敵軍**。
照引擎字面執行，敵軍可直接走上有守軍的指揮所格，斬首立即成立——警衛部隊等於不存在。

裁定：移動不得進入敵方戰鬥編隊所在的格，朝該格前進即為近戰突擊；
守軍被殲滅／投降／潰散／撤離後攻方才佔領該格；**斬首須真的奪下軍長所在那一格**。

**這條沒有改引擎**，而是規定裁判在解算腳本中不得對敵佔格呼叫 `advance`，
必須改呼叫 `battle`。兩局之間應把這個檢查移進引擎，否則它的可靠度等於裁判的注意力
（同 §十八 的教訓）。

### 二、同格多編隊只有一個挨打（裁示 48）

`bombard_hex` 以 `next(...)` 取該格第一個敵方編隊，**字典順序**決定誰承受全部火力。
同格三個編隊只有一個受損。這既任意又可被利用——拿一個營替一個師擋下整輪射擊。

裁定：該格所有敵方編隊都在彈著區內，一律承受；彈藥只消耗一次，
總發數按人數比例分攤，各自依自己的工事與能見計算損失。疊放不成為肉盾，也不放大戰果。

**已揭露的限制:** 物理上正確的答案更嚴厲——一格 4.52 km²，一個師佔地 4.00 km²，
兩個師擠一格代表各自被壓縮到一半面積、**彈著覆蓋率加倍**。
1944 年「不得在敵砲兵射程內密集集結」的準則正是為此。
本局不實施密度懲罰（規則已於 T0 凍結，該懲罰需改動 `impact_coverage`），
故本局的疊放**比現實安全**。此點已對雙方明白告知。

**兩局之間待辦：** 在 `impact_coverage` 中加入同格編隊數的壓縮項，
並把「不得移入敵佔格」移進 `plan_path`。

### 三、程序：反覆延長修改窗口

裁判曾宣告某一輪為「最後一次修改機會」，隨後又因新裁示而再度延長。
這本身不是瑕疵——缺口是在指揮官提問時才暴露的，而讓一方在資訊不完整下定稿才是不公。
但收束規則必須明確，故定案：

> **新裁示公告後，雙方各得一次在完整裁示集下的修改機會；兩方定稿即解算。
> 此後的提問仍受理，但答案自下一個 tick 起適用，不回溯、不重開已解算的 tick。**
