# 60 指揮 — 指揮所、命令延遲、命令與應變、提交窗口、裁示送達、斬首與勝負

> 本檔是本機能**唯一的規範住址**。數字表格由 `rulespec.py` 自引擎產生（`--sync`），散文可改、表格不要手改。
> 推導、史實依據與沿革在 `rules/v1_archive/`（封存，不再是規範）。


## §1 命令延遲階梯

### 2.1 三段指揮所

| 狀態 | 延遲 | 斬首風險 |
|---|---|---|
| **未建指揮所**（軍長隨隊臨時指揮） | **+2 級** | 無固定目標，不可斬 |
| **主指揮所**（通常設後方） | **+1 級** | 是斬首目標，但可設在深遠後方 |
| **前進指揮所**：其**周圍 6 格內**的編隊 | **基準（0 級）** | 是斬首目標，靠前易被斬 |

- **開局沒有任何指揮所。** 必須自行下令「在 (x,y) 建立主／前進指揮所」。
- 架設 **2 小時**生效；拆設同。移動指揮所期間退回「未建」的 +2。
- 可同時保有主與前進指揮所。**軍長在哪一個，那一個才是斬首目標。**
- 架設本身**不吃通訊延遲**（軍長自己的參謀團，判例 §六 R7）。

### 2.2 前進指揮所的兩個條件（缺一即不生效）

1. 軍長**駐於該指揮所**；
2. 受益編隊距該指揮所 **≤ 6 格**；
3. 該指揮所**位於本方編隊 x 座標中位數之前**（朝敵方向）。

第 3 條為 Run 6 之後補入：`precedents.md` §9.2 記載 Run 5 有一方把前進指揮所設在
**自己後方縱深的森林格**，零斬首風險取得 0 級延遲，
使設計上原本要互相交換的「節奏優勢 ↔ 斬首風險」完全脫鉤。

### 2.3 等級

| 等級 | 基準延遲 | 例 |
|---|---|---|
| **L1 反應式** | 1 小時 | 停火、改變射擊目標、啟動干擾 |
| **L2 戰術改變** | 2 小時 | 某師改變軸線、由攻轉守 |
| **L3 大重組** | 3 小時 | 整師反向撤退、跨軸調師、全軍轉向 |

實際延遲 ＝ 基準 ＋ 指揮所階梯的級數。**每條命令由下令方自行標註等級**；
裁判代為認定時只看動作性質——**裁判看不到你的意圖**。

## §2 命令的兩欄：命令欄與應變欄

**這是本檔最重要的一節，也是此前完全沒有住址的部分。**

| | 命令欄 | 應變欄 |
|---|---|---|
| 寫法 | `[L1] BLU-AD：具體動作 ＋ 目標座標 ＋ 姿態` | `若（具體條件）則（具體動作）` |
| 數量上限 | **8 條**／tick | **6 條**／tick |
| 生效時點 | 下令時刻 ＋ 延遲（§2） | **條件成立的當小時，零延遲** |
| 用過之後 | 成為常設命令，持續執行至被取代——**取代自新條款生效小時起，生效前舊條款照常展開**（判例 §二十八 28.3） | **用過即無** |
| 跨 tick | 常設命令跨 tick 延續 | **不跨 tick**，每 tick 重新登記 |
| 誰執行 | 依命令執行 | 裁判代為執行（故條件須可判定） |

### 3.1 零延遲是應變欄存在的唯一理由

命令欄吃延遲，是因為命令要經過參謀、通信、下達、部隊反應。
**應變是事前就下達完畢的**——條件成立時，部隊執行的是它早已收到並演練過的預案。
史實上這就是「若敵越過某線則引爆預設爆破」這類命令的運作方式。

**代價是它必須事前寫下，而你事前不知道會發生什麼。**
六條應變是六個猜測；猜錯就浪費，猜對就贏得兩小時。

> **Run 7 終局即為此**：一方的撤退令走命令欄（吃延遲），
> 另一方的突擊走應變欄（觸發即生效）——突擊比撤退早兩小時。

### 3.2 條件必須可由 state 客觀判定

「若情況不利」不是條件。「若敵裝甲編隊進入 (14,9) 或其相鄰格」是條件。

裁判依**最小解讀**執行（`arbiter_v2.md` §0）：在不替該方擴張行動範圍、
不替該方作戰術決定的前提下，取最保守的執行方式。
條件語意含糊時，裁判**不得替該方選擇有利的讀法**。

### 3.3 位移類的應變執行到完成為止

應變若為「移動至 (x,y)」，它會**執行到抵達或被阻止為止**，並付出移動的全部代價
（疲勞、POL、工事歸零、該小時不得砲擊）。它不會因為 tick 結束而停止——
位移是一個持續動作，不是一個瞬間事件。

### 3.4 登記與稽核

應變一經觸發，裁判必須在該 tick 的命令清單登記
（`runs/_manifest.TickOrders.contingency_fired(uid, src="紅軍 T8 應變第 2 條")`）。

理由：稽核的 A6 檢查「開火者是否有命令出處」，而應變觸發的射擊沒有火力任務登記。
**更重要的是：這使「哪一條應變在第幾小時觸發」進入稽核紀錄。**
Run 7 的應變決定了三個轉折，而它們只存在於命令的散文裡——事後無從機械查證。

### 2.5 命令格式

四段標題不得更改：`## 意圖`／`## 命令`／`## 應變`／`## 給裁判的問題`。命令欄每條自標 L1／L2／L3，寫編隊、動作、目標座標、姿態；
座標須在地圖內。可用動作：行軍（各姿態）／固守／構築工事／偽裝作業／抽離營級／歸建／砲擊〈敵編隊〉［急襲｜壓制｜干擾］／攔阻射擊 (x,y)／建立主／前進指揮所 (x,y)／示降／受降。
規則沒寫的動作一律得嘗試（00_核心 §2）。「給裁判的問題」只能問自己視角內合法的問題，不可問戰術建議；通則答案公告雙方。

## §3 提交窗口

1. **Tick 開頭**雙方同步提交，互不可見。
2. 逾時 ＝ 視為「繼續既有命令」。
3. **凡在某 tick 內公告新裁示，該 tick 的提交窗口即自動對雙方重新開啟**，
   且必須確認雙方都在「完整裁示集」下確認過（修改或明示不改）之後才得解算。
   「確認不改」與「修改」具有同等效力；**沒有回應不算**。（判例 §二十）
4. 新裁示公告後，雙方各得**一次**在完整裁示集下的修改機會；兩方定稿即解算。
   此後的提問仍受理，但答案**自下一個 tick 起適用**，不回溯、不重開已解算的 tick。
   （判例 §十九 之三）

## §4 裁示的送達

**裁示是規則，不是新聞。** 每一份簡報都必須附上該 tick 之前公告的**全部**裁示，
並標示「本回新增」哪幾份。（判例 §二十二）

Run 7 的 `dispatch.py` 初版只發當前 tick 的裁示，使一方**八條規則從未收到**，
其中包括「疲勞會壓低組織度上限」——而該方的常設命令讓三個師整夜行軍。
**它想要的和它下的令是相反的，而讓它能算出這件事的那條規則，它沒收到。**

簡報因此變長。這個成本是必須付的：**簡報過長只是不便，規則不一致是不公平。**

## §5 單方內容的唯一通道

- 單方事實**只能**經由程式產生的簡報送達（`arbiter_v2.md` §0）。
- 對指揮官的一切訊息，收件人一律用該 agent 的**完整名稱或識別碼**，
  不得用可能碰撞的簡稱。（判例 §十八：Run 7 T0 曾因少寫 `-2` 而誤送）
- **能寫進簡報檔的就不要用訊息送。** 簡報有洩漏檢查、有歷史副本、可稽核；訊息沒有。
  訊息只用於程序通知（「裁示已公告」「可修改命令」「請確認」）。
- 凡裁判主動核對的事實，若其性質為**通則**（門檻、算式、係數），
  一律公告雙方或寫進程式產生的簡報；不得只寫給提問的一方。（判例 §二十二 附）

## §6 斬首與勝負


1. **斬首即勝（sudden death）**：任一方**摧毀敵軍長所在的指揮所** → 立即獲勝。（見 §5 指揮規則）
2. **殲敵計分（時間到）**：撐到 Tick 8 結束，**擊毀敵方戰力較多**的一方勝。戰力＝以各編隊損失的人員＋裝備價值計。
3. **平手判定**：殲敵相當時，**自損較少**者勝。

> 無地形目標、無城鎮可佔——這是純粹的殲滅戰。時間上限逼雙方必須交戰，防止龜縮對峙。

- **斬首**：敵戰鬥或特戰編隊進入**軍長當前所在的指揮所格**並摧毀之 → 該方立即落敗。該格無守軍時，敵戰鬥單位進入即判定斬首（判例 R6，裁示 11）；有守軍時須先在近戰中擊敗或逼退守軍。
- 主指揮所也能被斬；敵方須穿透整條縱深。不建指揮所躲斬首則永遠吃 +2 延遲。
- 敵方**不會自動知道**指揮所在哪，須靠偵察發現（20_偵察 §3）。
- 終局判定順序：斬首即勝 → 殲敵較多 → 殲敵相當（差 ≤ 2%）時自損較少者勝 → 完全平手（40_近戰 §8）。劇本時長 54 小時（T0–T8），時間到由裁判宣告終局。
