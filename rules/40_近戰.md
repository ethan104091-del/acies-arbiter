# 40 近戰 — 戰鬥力、兵力比、兵種協同、戰術狀態、編成

> 本檔是本機能**唯一的規範住址**。數字表格由 `rulespec.py` 自引擎產生（`--sync`），散文可改、表格不要手改。
> 推導、史實依據與沿革在 `rules/v1_archive/`（封存，不再是規範）。


## §0 原則

戰鬥結果由確定量決定：兵力、組織度、補給、經驗、地形、能見（誰看到誰）、兵種協同、戰術狀態。
每小時重算：列出該格參戰編隊 → 各自戰力 CP → 兩邊合計 → 兵力比 → 對照表得雙方損失與逼退 → 組織度衝擊 → 狀態機（80_狀態）。

## §2 CP 乘數鏈

CP 的完整算式：

```
CP = 基礎值 × 戰力% × 組織度/100 × 補給係數 × 經驗倍率 × 疲勞戰鬥效力
     × 地形倍率 × 伏擊/被動 × 兵種協同 × 從行軍中接戰
```

## §4 逼退

逼退由引擎在近戰內**強制位移**執行，不受移動速率、疲勞、油料限制；守方向本方補給源方向退，攻方逼退反向。
守軍被清出該格後攻方進駐並棄自身工事（接收該格工事，50_工事 §2）。

## §5 近戰的發生

- 移入敵方戰鬥編隊所在的格即為**近戰突擊**（裁示 47）；不得以行軍進入。攻方須為明文受命者且已在相鄰格；守方為該格全部具戰鬥資格的編隊（裁示 56）。
- 雙方同時移入同一格為遭遇戰（裁示 57）。
- 突擊本身不算「移動過」（裁示 53）。

此節即為防止同類錯誤再發生——而它沒能防止本節自己在 Run 7 又錯一次。

## §7 戰術狀態逐時判定

`combat_v1.md:163` 載「從行軍中接戰｜該方 ×0.7（兩種一起算）」，**未說持續多久**。

**裁示：戰術狀態是「該小時的姿態」，不是整場交戰的持久標籤。**

`從行軍中接戰` 的判準為**該編隊該小時是否移動過**（`flags["moved"]`）——
純機械、零裁量、雙方同適用。衝入接戰的那一小時適用，
其後陷入近戰而未移動之小時**不適用**。

同一原則適用於 `combat_v1.md` §II 的全部戰術狀態：突襲、預設陣地、
被動應戰、突破後追擊、從行軍中接戰——它們全部描述「該小時在做什麼」。

### 這條裁示的作成過程有程序瑕疵，一併記載

裁判在 Run 6 終局**看到雙方僅差 7 分之後**才發現此錯誤，修正後計分由
「紅軍勝 7 分」變為「藍軍勝 769 分」。修正本身正確（執行錯誤，非規則變更），
但裁判的**稽核努力是不對稱的**——若首次結果即為一方大勝，該錯誤極可能不會被發現。

制度性修正：解算腳本應先跑完整自我稽核清單，**稽核通過才印出計分**。
詳見 `law/precedents.md` §十二。
